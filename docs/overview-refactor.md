# 院区与双页面重构验证记录

验证日期：2026-11-02。以下记录属于本地演示服务及浏览器验证，不代表实机或生产部署验证。

## 页面和设计

采用 design-taste-frontend 的应用界面流程，延续 Framed sheet，方向种子 169160782，保留原有字体及地图配色，未重抽方向。以真实拓扑地图和固定楼层地点作为界面主体，顶部使用明确的双页面导航。

概览回答“这一场的任务需求、机器人执行和资源使用如何”；任务回答“某个订单分配给谁、何时开始及沿哪条路线执行”。两页复用 Workspace、地图 Canvas 和应用轮询。

截图复核：

- 地图是主区域；概览底部指标保持紧凑且可折叠，任务页把空间留给记录。
- 概览左右边界与底边对齐；任务页机器人面板延伸至底部，左侧预留新建任务按钮。
- 楼层图只使用一个数据色；状态和主操作保留原有语义颜色，无虚构趋势。
- 实测六个订单：4F 1 单、5F 5 单；执行 2、等待 2、完成 2、失败 0。目的地点排行与楼层汇总一致。
- 冲突为 0 时处理率为 —；当前无电梯，明确显示未配置。没有用样例数字补齐空值。
- 节点标签继续与图例同色，布局没有新增内部区域名称。
- 390px 使用互斥抽屉，地图工具、新建任务和抽屉入口没有重叠；弹窗内滚动。

生产构建检查覆盖 1440、768、390px，两页均为 0 FAIL；保留 tiny-text 提示：11–12px 用于时间、能力、辅助说明、图例及指标标签，任务/机器人身份与主要数值为 13px 及以上，地点辅助行沿用紧凑字号。静态 lint 的浮层阴影提示只对应打开的演示控制菜单。没有为检查器隐藏界面。

## 实际浏览器交互

- 从任务页提交 `4F · P3 → 5F · P2` 配送，从概览提交 `4F · P8 → 4F · P1` 取货。跨层结果包含 13 个算法节点，两个订单完成，楼层汇总各 1 单；楼梯累计占用约 29.78 模拟秒。
- 切换双页面时旧 Canvas 仍连接在 DOM 中；中英文和明暗主题四种组合下再次验证两页均不重建 Canvas、无横向页面溢出及区域标识泄漏。
- 暂停前后间隔真实时间读取的完整状态相同；刷新和重选当前院区保留场次及任务。
- 连续提交四个样本订单，产生两个等待任务；等待项进入任务页并选中对应任务。普通排队没有被统计为规划冲突。
- 楼层入口及目的楼层组合筛选写入 URL；任务日志内容为英文，冲突事件空态正确，弹窗支持 Esc。
- 手机验证指标、概览和分布抽屉互斥，新建任务弹窗关闭后恢复地图。控制菜单支持 Esc 和外部点击关闭。

当前仅有一个演示院区、一段楼梯，没有电梯。冲突统计接入现有检测器；逐单流程不保证产生冲突，也没有新增跨批次安全策略。启动和指标口径见 README 及后端 demo/README.md。
